# Dart

Install with `dart pub add intrlay`, or `flutter pub add intrlay` in a Flutter
project. The runtime supports Dart 3.3 and later. Generate bindings with
`--language dart` and include them in your Dart package.

## Construct and read a drawing

Generate the [tutorial schema](../tutorial.mdx#1-define-the-message) with
`--language dart --output generated/drawing.dart`:

```dart
import 'generated/drawing.dart';
import 'package:intrlay/intrlay.dart' as intrlay;

void main() {
  const value = DrawingInput(
    title: 'Sketch',
    points: intrlay.SequenceInput.from([PointInput(x: 1, y: 2, z: 3)]),
    selectedPoint: null,
    command: DrawingCommandDrawPointInput(
      position: PointInput(x: 7, y: 8, z: 9),
      size: 0.5,
    ),
  );
  final drawing = DrawingView.create(value);

  assert(drawing.title == 'Sketch');
  assert(drawing.points[0].x == 1);
  assert(drawing.selectedPoint == null);
  final position = drawing.command.drawPointPosition;
  if (position != null) {
    assert(position.x == 7);
  }

  drawing.points[0].x = 10;
  drawing.selectedPoint = 0;
  drawing.command.replace(const DrawingCommandClearInput());

  final received = DrawingView(drawing.storage.bytes);
  assert(received.points[0].x == 10);
  assert(received.command.drawPointPosition == null);
}
```

Generated classes provide typed input values and separate buffer views.
Enums with payloads are a sealed input class with a concrete class for each
variant. Payload-free enums use a Dart enum whose `tag` is the declared wire
value, independent of its ordinal `index`.
Variant-specific getters return `null` when inactive; `tag` exposes the encoded
number. The final `storage` field exposes the shared `intrlay.Storage`.
`drawing.storage.bytes` is its `Uint8List`, and `drawing.storage.data` provides
numeric `ByteData` access. Borrowing them does not copy the payload.
The runtime shares buffer initialization and UTF-8 size calculation; generated
code keeps explicit typed accessors.

Collections with zero-initializable elements use `SequenceInput<T>` or
`FixedArrayInput<T>`. `.from(list)` borrows existing element storage;
`.zeroed(length)` requests a zero-filled sequence, and `.zeroed()` requests a
fixed array whose length comes from the schema. Existing lists need no wrapper
allocation. A zero-filled sequence uses one count object, while fixed arrays
use a shared marker; neither allocates the requested elements. Other collections
take ordinary lists. See
[Zero-initialized arrays](../concepts/buffers-and-views.mdx#zero-initialized-arrays).

## Numeric array inputs

Generate the [Samples schema](../concepts/buffers-and-views.mdx#numeric-arrays)
with `--language dart --output generated/samples.dart`. Collection inputs can
borrow typed lists directly:

```dart
import 'dart:typed_data';

import 'generated/samples.dart';
import 'package:intrlay/intrlay.dart' as intrlay;

void main() {
  final values = Float32List.fromList([1, 2, 3]);
  final matrix = Float32List(16);
  matrix[0] = 1;

  final samples = SamplesView.create(SamplesInput(
    values: intrlay.SequenceInput.from(values),
    matrix: intrlay.FixedArrayInput.from(matrix),
  ));
  matrix[0] = 2;
  assert(samples.matrix[0] == 1); // Encoding copied the input.
}
```

The `.from` inputs retain the typed lists without copying them or allocating
wrappers. There is no need to call `toList`. Writers bulk-copy compatible lanes
into aligned construction buffers without an intermediate list. Ordinary lists,
scalar conversions, and unaligned mutation buffers retain element writers.

Small fixed arrays use element copying when range-copy setup would cost more.
Native and JavaScript builds use separate thresholds; the platform selection is
a compile-time constant, so it does not add a per-element runtime branch.
The array size and input representation still determine whether bulk copying
applies. JavaScript-target 64-bit integers retain element conversion.

## Caller-provided buffers

With `value` from the example and an import of `dart:typed_data`:

```dart
final bytes = Uint8List(DrawingView.computeByteLength(value));
final inPlace = DrawingView.createInPlace(bytes, value);
assert(inPlace.title == 'Sketch');
```

Use `DrawingView.alignment` when selecting a region within another buffer, and
keep its owner alive. Native FFI integrations can use a region exposed as a `Uint8List`;
web integrations can pass the same byte-oriented representation through their
chosen JavaScript bridge.

## Composite values

Scalar fields use Dart's numeric types. Numeric projections use typed lists such
as `Float32List`; structural collections retain typed child views. Common
`project` annotations can choose the desired API without changing the encoding.

Optional values use nullable types. Nested states such as an absent optional and
a present optional containing `null` remain distinct through `Some` wrappers.
Composite getters cache child views and reread optional/variant state after
replacement. Obtain the active child again when that state changes.

## Native and web execution

The same schema and byte layout work in Dart native and JavaScript builds.
JavaScript-target integer precision limits still apply: the generated `int` API
does not guarantee exact representation of every 64-bit integer in that target.
Choose values within the target's exact range when the application needs exact
IDs or counters, or define an explicit representation for wider values.

Storage requirements and mutation rules are described in
[Storage and ownership](../concepts/storage.mdx). Getter/setter generation and
numeric projection controls are in the [annotation reference](../reference/annotations.mdx).
