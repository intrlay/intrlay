# TypeScript and JavaScript

Install the ES-module runtime with `npm install @intrlay/runtime`, generate with
`--language typescript`, and compile the output with your TypeScript project.
The [getting-started example](../getting-started.mdx) includes a complete Node.js
consumer. The same views work with browser buffers.

## Native inputs and buffer views

Generate the [tutorial schema](../tutorial.mdx#1-define-the-message) with
`--language typescript --module-name drawing --output generated/drawing.ts`.
Construction takes structural input objects:

```typescript
import { DrawingCommandKind, DrawingView } from "./generated/drawing.js";
import type { DrawingInput } from "./generated/drawing.js";

const value: DrawingInput = {
    title: "Sketch",
    points: [{ x: 1, y: 2, z: 3 }],
    selectedPoint: null,
    command: { kind: DrawingCommandKind.DrawPoint, position: { x: 7, y: 8, z: 9 }, size: 0.5 }
};
const drawing = DrawingView.create(value);

console.log(drawing.title);           // Sketch
console.log(drawing.points.get(0).x); // 1
console.log(drawing.selectedPoint);   // null

const position = drawing.command.drawPointPosition;
if (position !== undefined) {
    console.log(position.x); // 7
}

drawing.points.get(0).x = 10;
drawing.selectedPoint = 0;
drawing.command.replace({ kind: DrawingCommandKind.Clear });

const received = new DrawingView(drawing.storage.bytes);
console.log(received.points.get(0).x);           // 10
console.log(received.command.drawPointPosition); // undefined
```

The constructor borrows bytes. `create` encodes a native input into newly
allocated storage. The readonly `storage` field exposes the shared `intrlay.Storage`;
`drawing.storage.bytes` is its `Uint8Array`, and numeric views such as
`drawing.storage.f32` address the same allocation.
Scalar accessors use TypedArrays; strings are decoded to JavaScript strings
when read. The runtime checks little-endian TypedArray storage once at load time.

## Numeric array inputs

Generate the [Samples schema](../concepts/buffers-and-views.mdx#numeric-arrays)
with `--language typescript --output generated/samples.ts`. Existing TypedArrays
can supply the numeric fields directly:

```typescript
import { SamplesView } from "./generated/samples.js";

const values = new Float32Array([1, 2, 3]);
const matrix = new Float32Array(16);
matrix[0] = 1;

const samples = SamplesView.create({ values, matrix });
matrix[0] = 2;
console.log(samples.matrix[0]); // 1: encoding copied the input.
```

Numeric array inputs accept `ArrayLike` values, so there is no need to convert
an existing TypedArray with `Array.from` or spread syntax. TypedArray inputs use
bulk `set` copies, including fixed arrays and nested numeric-array fields. Short
fixed arrays use element loops to avoid the type-check and range-copy overhead.
Ordinary arrays and other array-like objects use element writers. Differently
typed numeric lanes retain JavaScript's numeric conversion rules; `i64` and
`u64` inputs use `bigint` elements.

## Caller-provided buffers

Given `value` above:

```typescript
const bytes = new Uint8Array(DrawingView.computeByteLength(value));
const inPlace = DrawingView.createInPlace(bytes, value);
```

The region must satisfy `DrawingView.alignment` and the measured capacity.
Do not pass an input view that overlaps the destination. An application can use
an FFI-provided region in place of the allocation above if its lifetime is valid.
[Storage and ownership](../concepts/storage.mdx) shows an aligned slice of a
larger allocation.

## Composite values

Enums with payloads use a `kind` discriminant whose type is a generated numeric
`const enum`, such as `DrawingCommandKind`. Payload-free enums use a numeric
`const enum` input directly. Both preserve the declared wire tags. Compile these
modules with TypeScript; Node.js type stripping alone does not transform enum
declarations. Variant-specific view getters return
`undefined` for an inactive variant. `tag` returns the encoded number with its
enum type: `DrawingCommandKind` for a payload enum, or `Mode` for a
payload-free `Mode`. Fields and collection elements read `Mode` directly;
only explicit exports have a standalone `ModeView`. This adds no runtime
conversion. Optional
values use nullable APIs; nested optional states that would otherwise collapse into `null`
use a `Some<T>` presence wrapper. That distinction preserves `None`, `Some(None)`,
and `Some(value)`.

Record collections expose element views through `get(index)`. Mark the collection
field with `project = "indexed"` to add field helpers. For example, after adding
that annotation to `Drawing.points`, a loop can avoid creating an element wrapper:

```typescript
let totalX = 0;
const points = drawing.points;
for (let index = 0; index < points.length; ++index) {
    totalX += points.getX(index);
}
```

These field helpers require an in-range integer index.

Composite field getters cache views. They reread presence bits and enum tags so
that replacement through another view remains observable. Obtain an active child
again after a variant or presence change; do not retain an inactive payload view.

Numeric fixed arrays use TypedArrays by default. Common `project` annotations
can also flatten homogeneous records or request indexed field access. This can
avoid creating an element wrapper when reading a field in a tight loop.
Numeric projections include any padding lanes in their representation.

`i64` and `u64` scalar values use JavaScript `bigint`. Generated APIs retain
TypeScript types; choosing a numeric projection is an explicit request to expose
the lower-level representation.

## Generated API size

`generate_getters`, `generate_setters`, and `create` can omit unused code. These
are generation controls, not a readonly storage system. Returned TypedArrays
retain their usual operations. See [Schema annotations](../reference/annotations.mdx)
for scope, projection, and indexed-access rules.

Input types are emitted only when construction or mutation needs them. Enum
declarations remain available for reading tags even without a construction API.
