# Code generation

The `intrlay` executable generates typed buffer views from compiler-resolved
metadata. Install it with `cargo install intrlay-cli`, download an executable
from [GitHub Releases](https://github.com/intrlay/intrlay/releases), or build
it from a checkout with `cargo build --release -p intrlay-cli`.

The target languages are `rust`, `cpp`, `typescript`, `csharp`, `python`, and `dart`.
Generated bindings use the corresponding Intrlay runtime package.

## Rust input

Define types in a Rust library and declare its exports at the crate root:

```rust
#[derive(intrlay::Intrlay)]
pub struct Command {
    pub id: u32,
    pub label: String,
}

#[derive(intrlay::Intrlay)]
pub struct Message<T> {
    pub value: T,
}

intrlay::export_types! {
    Command,
    IntegerMessage = Message<i32>,
}
```

List the export roots explicitly; their reachable field types are collected
automatically. The CLI does not scan for every type with an `Intrlay` derive.
This macro is required by the manifest-based collection path, not by ordinary
Rust view use. The [metadata API](#exported-metadata-input) provides a separate
way to build the export list programmatically.

Generate directly from the library's manifest:

```sh
intrlay generate --manifest-path crates/protocol/Cargo.toml --language typescript --output generated/bindings.ts
```

The CLI builds and runs a temporary Cargo collector that depends on the selected
library. The collector calls the metadata entry point generated by
`export_types!`, then the CLI passes that metadata to the shared code generator.
Only the library and its dependencies are compiled. A separate schema library
keeps application binaries and unrelated dependencies out of this build.

Cargo and rustc must be installed; they are not bundled with the executable.
The compiler and derive macro resolve aliases, generic specializations, and
attributes. Export entries may reference qualified paths or private types.
Entry attributes such as `#[cfg(feature = "extra")]` follow normal Rust
compilation. Invoke `export_types!` once at the crate root.

For a workspace, select a library package explicitly when needed:

```sh
intrlay generate --manifest-path Cargo.toml --package protocol --features extra --language csharp --output generated/Bindings.cs
```

These options apply only to `--manifest-path` input:

| Option | Effect |
| --- | --- |
| `--package NAME` | Select the schema package in a workspace. |
| `--features a,b` | Enable features on the selected library. |
| `--all-features` | Enable all its features. |
| `--no-default-features` | Disable its default features. |
| `--offline` | Prevent Cargo network access. |

Collection runs on the host architecture, even when the application selects a
cross-compilation target. Schema definitions must compile for the host;
target-dependent `cfg` uses that host configuration. Cargo configuration and
toolchain discovery run from the selected package directory. Workspace dependency
overrides and profiles are carried into the temporary project. An existing
lockfile seeds dependency resolution and is left unchanged, as is the source
crate. Compiled dependencies are cached under `<cargo-target-dir>/intrlay/rust`.

## Exported metadata input

Build tools can also collect metadata through the Rust API:

```rust
let mut registry = intrlay::schema::Registry::new();
registry.export::<Command>("Command");
std::fs::write("schema.json", registry.finish().to_json()?)?;
```

`schema.json` describes types for code generation. It is not the application
payload format. Generating from it requires neither Cargo nor rustc:

```sh
intrlay generate schema.json --language typescript --output generated/bindings.ts
```

## C++ input

Include `intrlay/annotations.hpp` and annotate the source declarations. Extract
metadata, then use the same generator as for Rust:

```sh
intrlay extract-cpp schema.hpp --output schema.json -- -Iinclude
intrlay generate schema.json --language cpp --output generated/bindings.hpp
```

Replace `include` with the path to Intrlay's headers. The
`--compilation-database build` option reads the input translation unit's flags
from `build/compile_commands.json`. Arguments after `--` are forwarded to Clang.

Only `extract-cpp` requires libclang and a C++20 standard library/toolchain.
Install LLVM and set `LIBCLANG_PATH` to the directory containing `libclang.dll`,
`libclang.so`, or `libclang.dylib` if discovery needs an explicit path.
Executable archives include Intrlay's headers, but not a C++ compiler or
libclang. Generating from existing metadata does not load libclang.

The [C++ guide](https://intrlay.github.io/intrlay/languages/cpp/)
contains a complete source declaration and runtime integration example.

## Output options

`--options options.json` accepts a serialized `GenerateOptions` value.
`--module-name DrawingProtocol` names the generation unit independently of its
exports and overrides `module_name` in the options file. The default is `Schema`.
Adding or removing an export does not rename the module.

C++ uses `intrlay_generated::drawing_protocol` for that module name; C# uses
`IntrlayGenerated.DrawingProtocol`. Override those namespaces with an options file:

```json
{
  "cpp_namespace": "app::protocol",
  "csharp_namespace": "App.Protocol"
}
```

Namespace segments must be ASCII identifiers, separated by `::` or `.`. Their
spelling is preserved independently of the symbol naming policy. Each generation
unit retains its own types and helpers; namespaces do not deduplicate shared
types across generated files.

Module-wide naming policies select symbol kind, visibility, and modifiers such
as `static` or `readonly`, then apply a casing preset and optional prefix/suffix.
Explicit annotation names are exceptions to that policy. The runtime package's
own API names remain fixed. [Generated names](https://intrlay.github.io/intrlay/reference/naming/)
contains a complete options file, selector reference, and before/after examples.
See [Schema annotations](https://intrlay.github.io/intrlay/reference/annotations/)
for projections, accessor generation, adapters, and derive configuration.

Run `intrlay generate --help` or `intrlay extract-cpp --help` for command help.
