Intrlay generates typed views over binary buffers from Rust and C++ type
definitions. It lets cooperating programs exchange structured data across FFI,
WebAssembly, and IPC boundaries without rebuilding an object tree just to read
a field.

Define a schema in **Rust or C++**, then generate APIs for **Rust, C++,
TypeScript, C#, Python, and Dart**.

## From a value to a view

```text
Rust / C++ declarations ── generate ──> typed APIs in six languages

Native value ── encode ──> buffer ── borrow ──> view.field
```

Declare records, payload-bearing enums, optional values, arrays, strings, and
owned trees in a source language. The generator gives each target a typed way
to construct the shared representation and access its bytes.

Views follow each language's conventions: Rust borrows, C++ value types, C#
structs and spans, TypeScript TypedArrays, Python memoryviews, and Dart typed
data. The binary representation stays consistent across those APIs.

See [Feature comparison](feature-comparison.mdx) for the differences from
FlatBuffers, Cap'n Proto, rkyv, serde-generate, SBE, and Protocol Buffers, including
when another approach is a better fit.

Intrlay targets cooperating producers and consumers that agree on a schema.
Rust and C++ provide checked view constructors and explicit unchecked paths;
other targets' views assume valid encodings. The application manages transport,
schema selection, buffer lifetime, and synchronization.
